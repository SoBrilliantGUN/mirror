# 技术方案 · 对话增强三件套

> 让陪伴者「更像真人」的三件行为增强：**换话题**（不感兴趣检测）、**联网搜索**（真查博查）、**具体夸赞**（情绪价值）。三件都落在实时语音对话的 `respond()` 热路径 + `brain/` 上下文装配，不改动 L0/L2 语音链路与长期记忆。

## 一、换话题（不感兴趣检测）

**目标**：用户对当前话题兴致不高时，陪伴者主动换话题，别硬聊。

**判定规则**（两条信号是「且」关系，缺一不可）：

| 信号 | 来源 | 阈值 |
|---|---|---|
| 唤醒偏低 | `scoreAffect` 输出的 `arousal` | `arousal < 0`（平静/低能量一侧） |
| 回复延迟 | 陪伴者说完 → 用户开口的间隔 | `> 3000ms` |

> 为什么不是「单独低唤醒就算不感兴趣」：低唤醒也可能是「平静放松地慢慢聊」，那是好事。只有**既唤醒低、又回复慢**，才指向「无聊、不想聊」。

**连续 3 轮**都命中 → 触发换话题；任意一轮唤醒正常或回复快 → 清零重计；陪伴者主动追问/轻问（用户没答）打断计数；新通话重置。

**实现**（纯函数 + 会话级状态机）：

```ts
// brain/interest.ts —— 纯函数，可单测
export const AROUSAL_LOW = 0;
export const REPLY_SLOW_MS = 3000;
export const DISINTEREST_LIMIT = 3;

export function evaluateDisinterest(arousal: number, latencyMs: number, prevStreak: number) {
  const hit = arousal < AROUSAL_LOW && latencyMs > REPLY_SLOW_MS;
  if (!hit) return { streak: 0, switchTopic: false };
  const streak = prevStreak + 1;
  return { streak, switchTopic: streak >= DISINTEREST_LIMIT };
}
```

- **计时基准**：`agentDoneAt` 挂在 `onPlaybackEnd`（陪伴者**真正说完**那一刻，不是「生成完」），`markUserVoice` 里算 `now - agentDoneAt` 记一次 `lastReplyLatencyMs`。
- **换话题落法**：触发时往本轮生成 prompt 注入 `[TOPIC]` 软信号块，让 LLM 按现有「找话题优先级」主动换话题（复用 `BLOCK_CONVERSATION` 的优先级：对对方好奇 → 兴趣爱好 → 工作 → 讲自己）。

```
[TOPIC] 对方连续几轮对这个话题兴致不高（唤醒低）、回复也偏慢，明显不感兴趣了。
这一轮别延续当前话题，主动换个话题（优先级：①对对方好奇 ②兴趣爱好 ③工作 ④实在没话说讲你自己），
自然过渡，别生硬说"我们换个话题吧"。
```

## 二、联网搜索（博查真查）

**目标**：用户提到陌生词、或纠正陪伴者的错误说法时，陪伴者「我查一下…」→ 真联网搜 →「哦，原来是 xxx」，带人为延迟，像真人刚查完。

**触发条件**（两条路都查）：

1. **正面求助**：用户直接问「xxx 是什么 / 什么意思」，而模型不认识这个词。
2. **被纠正**：模型「不懂装懂」说错了，被用户纠正（事实纠错，非观点分歧）。

> 平时模型照常回答、不主动暴露「我不会」（那不像人）；只有被纠正、或直接被问到一个它没把握的词时，才去查。

**动作时序**（关键：边查边嘟囔，盖住搜索延迟）：

```
识别到需要查
 → 先说「我查一下… / 我看看…」（filler，直接 TTS 播出，不 end 保持 speaking）
 → 并行发起博查搜索；即使 1s 就搜到，也人为留 ~1.5s 自然延迟（MIN_SEARCH_MS）
 → 拿到结果，追加 tool 消息，流式生成「哦，原来是 xxx」→ 逐句 TTS → end
```

**博查 Web Search API 接入规格**（公开 API）：

| 项 | 值 |
|---|---|
| 端点 | `POST https://api.bochaai.com/v1/web-search` |
| Header | `Authorization: Bearer <api_key>`、`Content-Type: application/json` |
| Body | `{ "query": "<搜索词>", "count": <条数> }` |
| 响应 | `data.webPages.value[]`，字段 `name` / `url` / `snippet`（`summary` 作回退） |

- **优雅降级**：未配 `BOCHA_API_KEY` 时搜索能力关闭，主链路照常（仿 NLS 哭/笑检测的降级模式）。
- **普通轮零回归**：只在「直接问 / 被纠正」候选轮（`isSearchCandidate` 纯文本启发式）才走非流式工具循环；其余轮次维持现有 `streamMessages` 流式，不额外吃延迟。
- **工具定义**：复用 `llm.chatWithTools`（OpenAI 兼容 function calling），工具 `search_web` 的描述里写清触发条件，让模型自己判断「这轮要不要搜」。

## 三、具体夸赞

**目标**：大致每说 10 句里有 3 句是**具体夸赞**，满足自恋、给情绪价值。

**口径**（与「不迎合」内核对齐，不冲突）：

- **具体夸**：夸对方真实做对 / 想明白的具体点（「这事你能自己捋清楚，挺厉害」），不是泛泛的「你真棒」。
- **大致密度**：约 3/10，不硬计数；只夸真事、别夸大、别每句都夸（夸过头就假）。
- **不违背「不迎合」**：夸的是真的，该温柔反对时照样反对。

**实现**：纯 prompt 层，新增 `BLOCK_PRAISE` 块进 `buildGenerateSystemPrompt`。若实测密度偏了，再加轻量计数器注入 `[PRAISE]` 软信号。

## 六、验证

1. `npm run typecheck` 全绿。
2. `npm test`：新增 `interest.selftest.ts`（3 轮命中 / 中途重置 / 单独低唤醒或单独慢不触发）、`search.selftest.ts`（`parseBochaResult` / `isSearchCandidate`）。
3. 实机（`npm run start` + 通话）：
   - **换话题**：连续 3 轮冷淡 + 慢回 → 主动换话题；中间一轮正常即重置。
   - **搜索**：问生僻词「是什么」或故意纠正 → 「我查一下…」停顿后「哦，原来是 xxx」；无 key 行为照旧。
   - **夸赞**：夸赞具体、不过密、不与「敢温柔反对」打架。
