# 技术方案 · L1 实时传输（具体实现）

> 从 `技术方案.md` §三 L1 行拆出。browser↔server 双工通道：双向音频 + 控制信令。已实现（`apps/server/src/rtc/webrtc.ts`）。

## 一、架构与选型

- **两端不对称**：浏览器用原生 `RTCPeerConnection`；服务端用 **werift**（纯 TS 的 WebRTC 实现，`apps/server/src/rtc/webrtc.ts`）当 peer。
- **音频 codec**：Opus only（`codecs: { audio: [useOPUS()], video: [] }`），无视频。
- **编解码**：`opusscript`（OpusScript），48kHz 单声道、VOIP 应用档。上行 decode、下行 encode。
- **信令**：**HTTP POST `/rtc/offer`**（非 WebSocket）交换 SDP；另有 `GET /health` 供前端健康轮询。

## 二、上行（你说话 → 服务端）

```
浏览器麦克风 → Opus 编码 → WebRTC RTP → 服务端
  pc.ontrack → track.onReceiveRtp → opus.decode(48kHz PCM)
    → resample(48k → 16k) → cbs.onUserPcm(Uint8Array 16kHz PCM)
```

- `onUserPcm` 是**16kHz 单声道 PCM 唯一咽喉点**：ASR、副语言特征、哭/笑检测、backchannel 四路都在这里接入（见 L2 文档 §四）。
- 解码失败只 `console.error`、不抛，单包坏不影响链路。

## 三、下行（服务端 → 你听到）

```
pushAgentPcm(24kHz PCM, gain?)
  → resample(24k → 48k)  → 播放队列 pcm48Queue
  → pacer 每 20ms 取一帧(960 samples @48kHz) → opus.encode
  → RtpBuilder 打 RTP（时间戳逐帧 +960）→ sendTrack.writeRtp
```

- **TTS 输出 24kHz PCM**（CosyVoice），重采样到 48kHz 再编码；重采样用**窗口化 sinc**（`rtc/resample.ts`：升采样抗镜像、降采样抗混叠）——线性插值升采样会在 12–24kHz 制造频谱镜像、听着发金属；`gain` 参数做鸭音（backchannel 用，默认 1.0，在重采样后的新数组上乘，不污染缓存片段）。
- **帧节奏 pacer**：`nextFrameAt += 20`（真实墙钟，不靠估算总时长），队列空即停、有新 PCM 再重启；播放节奏跟实时对齐，句与句自然衔接。
- **收尾**：`end()` 把末尾不满 20ms 的残余补静音发最后一帧（否则最后音节被吞）；`clear()` 打断时清空队列 + 停出帧（立刻停声）。

## 四、控制信令（data channel）

- 浏览器 `createDataChannel('control')`，服务端 `pc.ondatachannel` 监听 `onmessage`。
- 消息是 JSON：`{"type":"interrupt"}` → 回调 `onInterrupt()`；非 JSON 忽略。
- 打断链路：前端 VAD 上升沿发信令 → 服务端 `onInterrupt` → 作废当前 respond（`currentGeneration++`）+ `currentAbort.abort()` + `rtc.clear()` + `backchannel.reset()`。

## 五、ICE（Docker 下语音能否通的关键）

- **非 trickle**：`waitForIceGathering()` 等 `iceGatheringState === 'complete'`（3s 超时兜底），把 host candidate 写进 SDP 一次性交换，不搞 trickle 逐步补。
- **固定端口段 + 额外宣告地址**（`RtcIceOptions`）：
  - `icePortRange: [50000, 50100]` —— 与 `docker-compose.yml` 发布的 `ICE_PORT_RANGE` UDP 段一致，浏览器能经这段直达容器（只宣告、不绑定）。
  - `iceAdditionalHostAddresses: ['127.0.0.1']`（`ICE_HOST_ADDRESS`，远程填公网/LAN IP）。
- **局限**：本地 host 候选，无 STUN/TURN；Docker Desktop（Windows/Mac 的 NAT 隔离）下点对点音频连不通（网页/通讯录/信令正常），Linux/WSL2 原生 Docker 用 `network_mode: host` 可通。公网 STUN/TURN 留到「待后续」。

## 六、对外接口（缝）

```ts
type RtcCallbacks = {
  onUserPcm: (chunk: Uint8Array) => void; // 16kHz PCM（喂 ASR）
  onInterrupt: () => void;
};
type RtcPeer = {
  handleOffer(offerSdp): Promise<string>;   // 出 answer SDP
  pushAgentPcm(chunk, gain?): void;          // 24kHz PCM 入播放队列
  end(): void;                               // 冲末尾残余
  clear(): void;                             // 打断清队列
  close(): void;
};
```

> `onUserPcm` / `pushAgentPcm` / `onInterrupt` 就是 L1 与 L0/L2 之间的缝：上层只认「16kHz PCM 进、24kHz PCM 出 + 打断事件」，换传输（WebSocket ↔ WebRTC）不改上层。
