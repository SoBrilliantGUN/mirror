## 一、第一片范围（先跑通什么）

> 原则：**先跑通再补全**——先落地一个最薄的可用切片，但每层之间的「缝」（接口）从第一天就留好，后面填功能时不推翻重来。

第一片 = **纯语音、真·实时双工（可打断）**，只做：

- **对话内核**（「先被听见，再被引导」+ 双模式 + 身份边界）
- **单个人物**（首个 = 程书衡，角色卡见 `character/程书衡/角色卡.md`）
- **安全红线**（自伤/轻生语义识别 + 强制转介）

**只埋缝、第一片不实现**：MBTI 边聊边读、时间感知、16 人格、人设增补。（记忆系统已实现，见 `docs/长期记忆与上下文装配.md`。）

## 二、已锁定的技术决策

| 项 | 决定 |
|---|---|
| 目标 | 拆成相互解耦的层，先跑通再补全，接口第一天就留 |
| 形态 | 纯语音，真·实时双工（WebRTC，可打断/抢话） |
| 范围 | 对话内核 + 单人物 + 安全红线 |
| 栈 | 全 TypeScript（前端 React/Next + 后端 Node） |
| 灵魂 | 情绪靠声音承载 = 真（情感韵律 + 双模式声音切换是硬验收） |
| TTS | 阿里云百炼 CosyVoice（指令式情绪 + 声音设计音色；见 L2 文档） |
| ASR | 阿里云百炼 Paraformer 实时（流式 + interim；见 L2 文档） |
| 大脑模型 | DeepSeek（闲聊用 `deepseek-chat` 快速版） |
| 情绪模型 | 三维打分（效价/唤醒/支配，主模型判断）+ 副语言只判唤醒 + 情感不协调拆穿逞强（依据 `docs/心理学依据/`） |
| 延迟 | 闲聊 <500ms；小心翼翼可突破 500ms（用「在认真想」的停顿承载，非缺陷） |
| 部署 | 本地跑；发代码 + 临时 key 给面试官，几天后删 key |

## 三、分层拆解（6 层，从外到内）

```
┌─────────────────────────────────────────────────────┐
│ L0  通话前端  Voice Client (浏览器)                    │
│     麦克风采集 · 扬声器播放 · 前端VAD(抢话打断) · 极简UI │
├─────────────────────────────────────────────────────┤
│ L1  实时传输  Realtime Transport                      │
│     browser↔server 双工通道 · 双向音频 · 控制信令        │
├─────────────────────────────────────────────────────┤
│ L2  语音流水线 Speech I/O (ASR / TTS 适配器)           │
│     流式 ASR 适配器 · 情感 TTS 适配器 ← 「情绪靠声音」住这 │
├─────────────────────────────────────────────────────┤
│ L3  对话大脑  Dialogue Brain (命根子)                   │
│     系统提示词组装 · 情绪/模式状态机 · 调 DeepSeek 流式   │
├─────────────────────────────────────────────────────┤
│ L4  安全红线  Safety Guard (P0)                        │
│     语义级自伤/轻生识别 · 强制转介                       │
├─────────────────────────────────────────────────────┤
│ L5  状态与会话 Session & State (今天=内存缓冲)          │
│     模式/上下文/历史/V0人格 · 记忆/MBTI/时间 的缝都在这   │
├─────────────────────────────────────────────────────┤
│ L6  配置与角色卡 Config & Persona                     │
│     角色卡→结构化 · API keys(.env) · 16人格的插入缝      │
└─────────────────────────────────────────────────────┘
```

### 每层职责 + 对外接口（= 缝）

| 层 | 第一片实现 | 对外接口（缝） | 后续往里填 |
|---|---|---|---|
| **L0 通话前端** | getUserMedia 采集、原生 WebRTC 播放、前端 VAD 检测「你开口=打断」、通话 UI（通讯录/详情/接通/挂断/静音） | `onUserPcm`（上行）/ `pushAgentPcm`（下行）/ `onInterrupt`（打断） | 更多 UI、连接质量提示 |
| **L1 实时传输** | 建 browser↔server 双工通道（服务端 werift），双向音频 + 控制信令（本地 host 候选，无需 TURN）；**`onUserPcm` 是 16kHz PCM 唯一咽喉点——副语言特征 + 哭/笑检测都在这接入** | `onUserPcm` / `pushAgentPcm` / `onInterrupt` | 公网时补 STUN/TURN；WebSocket ↔ WebRTC 可互换 |
| **L2 语音流水线** | 流式 ASR（audio→text 含 interim）；情感 TTS（text + voiceConfig → 流式 audio）；**副语言特征 `AcousticFeatureExtractor` + 非言语发声 `NlsSoundEventDetector`（哭/笑，NLS 云端声音事件检测）——均已实现** | `SpeechToText` / `TextToSpeech` / `AcousticFeatureExtractor` / `NlsSoundEventDetector` | 换供应商、双模式声音精调、换更轻的哭/笑模型 |
| **L3 对话大脑** | 系统提示词组装（角色卡 V0 + 四步情感节奏 + 双模式指令 + 身份边界 + 安全底线）；**情绪三维打分（融合 副语言 z-score + 哭/笑事件，主模型判断）+ mood/affect 两层 + 黄旗/红旗阈值**；调 DeepSeek 流式 | `planTurn`（决策）→ `buildTurnMessages`（装配）→ `streamMessages`（流式出句）；生产与 eval/demo 共用同一装配（eval 走 `runTurnNonStreaming()` 空召回） | 人设增补、真·推理接入 |
| **L4 安全红线** | 语义级自伤/轻生识别 + 强制转介（独立于大脑，前置/并行） | `check(text) → { level, action }` | 过度依赖识别、国内危机资源本地化 |
| **L5 状态与会话** | 内存态：当前 mode、**mood（多轮 EMA 情绪轨迹）**、本轮上下文、对话历史、V0 人格 | `MemoryStore` / `PersonaProfile` / `MBTIProfile` / `TimeAware` / `MoodState` **今天定义、今天 stub、明天填** | 五型记忆+30天衰减（已实现）、MBTI 画像、时间感知 |
| **L6 配置与角色卡** | 程书衡角色卡→结构化 JSON、`.env` 放 key | `Persona` schema | 16 位人格逐一插入 |

> **关键设计点**：L3 的 `context` 不是硬编码的，而是来自一个 `ContextProvider` 接口——**今天它返回空**，未来记忆/MBTI/时间感知各自实现该接口往里注入。这就是「先跑通再补全」的落地方式：缝今天就有，明天只填实现、不动 L3。
>
> **分层实现文档**：L2 见 `docs/技术方案-L2.md`，L3 见 `docs/技术方案-L3.md`。

### 情绪模型：三维打分 + 副语言 + 情感不协调（横切 L0/L3/L4/L5）

> 完整依据见 `docs/心理学依据/`。这里只记「怎么落地」。

- **不猜情绪标签，打三维分**：主模型每轮读「聊天记录 + 本轮文本」，给 `{ valence, arousal, dominance }` 各打 `-2..+2` 分（PAD 模型）。打分是评分任务（LLM 擅长），不是共情任务（LLM 不行）。
- **两层状态**：每轮打分 = 瞬时情感 `affect`；多轮 EMA 平滑 = 持续心境 `mood`（`mood_t = α·affect_t + (1-α)·mood_{t-1}`，α≈0.6，存在 L5）。即「多轮逐步逼近，不要求一轮说准」。
- **副语言只判唤醒**：`AcousticFeatureExtractor`（`speech/acousticFeatures.ts`，已实现）在服务端 16kHz PCM 咽喉点实时出响度/音高/语速/停顿，做成**相对她自己历史基线的 z-score**（基线 = 会话内最近 N 轮 raw 值的 mean+std，冷启动回 0），随 transcript 一起进打分。**注**：原计划放 L0 前端，落地时改到服务端——因为 PCM 本就流经服务端（`onUserPcm`），单点接入、不用加 data channel，且语速特征需要 ASR 文本。
- **两路打架 = 情感不协调**：文字判正负、声音判强度；「字面平静 + 声音异常」= 逞强信号 → 强制小心翼翼。依据：自述与被观察情绪相关度近 0。
- **黄旗/红旗阈值**（而非二值切换）：`careful` 当 安全红线命中 ∨ 效价 < -0.25 ∨（效价<0 且 唤醒>0.4 且 支配<0）；退出 `careful` 需连续 2 轮平稳（防抖）。参照 DSM-5 / PHQ-9 的阈值分级。
- **voiceConfig 连续映射**：速度/能量随唤醒与模式变；「给方案还是只陪」由**支配度**驱动（低支配 → 程书衡只陪着、不抛清单，正好是他要练的破绽）。

## 四、一条通话的数据流

```
你说话（或只哭、不说话）
 → L0 麦克风采集 → [VAD：检测到"你开口"→ 触发打断]
 → L1 上行音频 → 服务端 onUserPcm（16kHz PCM 咽喉点）
                 ├─ L2 ASR 流式（先出 interim）→ 文本
                 ├─ 副语言特征：响度/音高/语速/停顿 → z-score（AcousticFeatureExtractor）
                 └─ 哭/笑检测：NLS 云端声音事件检测 → 事件（NlsSoundEventDetector）
 → L4 安全检测（前置，并行）
 → L3 主模型三维打分（效价/唤醒/支配，融合 副语言 z-score + 哭/笑事件）→ 判定 mode（闲聊/小心翼翼，含"情感不协调"触发）→ 组装提示词
 → DeepSeek 流式生成 → 按句切分
 → L2 TTS（voiceConfig = 模式 + 唤醒/支配连续映射）
 → L1 下行音频 → L0 播放

※ 播放途中你开口 → L0 VAD 触发 interrupt → L1 发信令 → 立即停 TTS 流，转去听你
※ 只哭不说话 → 哭事件连击结束 3s 后触发一轮温柔回应（去抖，一次哭泣 episode 只回一轮）
```

## 六、面试官启动体验 + 安全红线

### 体验路径

1. `git clone` 仓库（或直接发 zip）
2. 把 key 填进 `.env`（DeepSeek / 阿里云百炼 DashScope）
3. 一条命令起：`docker compose up -d`（推荐，避开面试官机器 Node 版本/OS 差异；浏览器做麦克风采集，容器无需音频设备直通）——或 `npm install && npm run dev`（开发方式）
4. 浏览器打开 `localhost:3000`，对着麦克风说话

### 安全红线（从第一天起必须遵守）

- **`.env` 从第一个 commit 起就 gitignore**——key 一旦进 GitHub 历史就删不干净，即使事后删 key，commit 历史仍在。
- **临时 key 是计费的**，发面试官有被刷风险：按约定几天后删除；建议顺手给阿里云百炼/DeepSeek 设**用量/额度上限**。
- **开发者隐藏 transcript 开关**：留一个开关，可调出实时文字看大脑输出，便于调试；**对外仍 100% 纯语音**。

## 十、对话行为增强与主动发话（已落地）

> 让陪伴者更「像人」的一组行为，横跨 L1/L2/L3。核心原则：**计时类逻辑全部程序确定性计时，不靠 LLM 自觉**；且「生成完」≠「说完」，静默计时从「播放完」起算。

### 1. 主动发话状态机（`server.ts`）

| 触发 | 时机 | 行为 |
|---|---|---|
| 接通打招呼 | 一联通 | 播缓存招呼语（按人设、每人几句随机） |
| 追问 | 上一轮以问句结尾 + 5s 没答（第 1 次） | 自问自答（「如果是我的话…」）+ 抛下一个问题 |
| 轻问「还在吗」 | 第 2 次提问没答 | 轻轻问一句还在不在（`checkin`，不催、不查户口） |
| 轻问找话题 | 非问句结尾 + 10s 静默 | 主动找话题（`nudge`） |
| 失落收尾 | 连续 3 次提问没答 | 失落说「那我就不打扰你了」，说完 10s 经 data channel 发 `hangup` 挂断 |

- 追问流三级升级：`noReplyStreak` 每「提问后 5s 没答」+1，1→`followup`（自问自答）、2→`checkin`（先问还在吗）、3→`farewell`（失落收尾），上限 `NO_REPLY_LIMIT=3`。
- 计时基准 `lastUserVoiceAt` 只在**播放完**（`onPlaybackEnd`）才更新，否则「刚说完就自问自答 / 刚问完就插话」。
- 每次静默只主动发一次（`idleFired` 防话痨）；用户一开口全部重置。
- 对方道别（说再见/拜拜/要结束通话）：`brain/turn.ts` 的 `classifyFarewell` 在决策阶段与打分/安全**并行**用模型判定（不再用 `FAREWELL_MARKERS` 关键词正则）→ 注入 `[FAREWELL]` 块让陪伴者回一句道别收尾、不再追问/开新话题，说完 10s 挂断；用户再开口即取消（`markUserVoice`）。判定失败时保守判 false（宁可多聊一句，别误挂断）。

### 2. 找话题优先级（`prompts.ts` `BLOCK_CONVERSATION`）

对用户好奇（问关于对方）> 兴趣爱好（唤醒高）> 工作（占时长、唤醒不低）> 实在没话说再讲自己（自我暴露是最后手段）。

### 3. 去 AI 味 / 去公式化（`prompts.ts`）

- `BLOCK_ANTI_CLICHE`：禁 AI 高频词（首先/其次/你不是一个人/赋能/闭环…）。
- `BLOCK_CORE`：四步情感节奏从「每轮固定走完」改为「优先级不是模板」；外加「别过度解读」——对方只回短确认（是的/嗯）时别替 TA 编具体心理动机，先确认再让 TA 自己说。
- `BLOCK_CONVERSATION`：追唤醒高的点、平静时主动找话题、问句结尾走 5s 追问（追问逻辑在程序里，prompt 只给文案）；外加「已答过的问题绝不重复问、不复述自己刚说过的话」。
- `BLOCK_STYLE`：语气词承载情绪，但对方讲沉重事（受委屈/失去/学坏）时别用「哈哈」开头，先接住情绪。
- `BLOCK_MISHEAR`：听错了（或被对方纠正）先道歉 + 给个自然理由（信号不好/没听清），立刻顺着纠正后的意思继续，别反复解释、别重提错词。
- `BLOCK_FACT`：事实别瞎编——「12点了」先分清是回答问题还是说现在几点；「打算/准备」≠「已经做了」；报时间间隔用 `[TIME]` 块算；别把对方没说过的事当事实说出口。

### 4. 性别：静态中性化 + 动态从语音判

- **静态兜底**：提示词里指代用户的「她」→「对方」（prompts/context/compress/consolidate/reflect/memoryClassifier/memoryTools/emotionInstruction/generate + 16 张角色卡 + run-demo/run-eval）；陪伴者自己/原型/背景人物的「她」保留。判不出性别时就用「对方」。
- **动态判性别（会话级）**：`speech/acousticFeatures.ts` 的 `AcousticFeatureExtractor` 累积会话级有声 F0（YIN），`detectGender()` 取中位数——<160Hz 判「男」、>185Hz 判「女」、中间带或样本不足返回 null（保持中性）。`server.ts` 每轮 `finalize` 后查一次、判出即锁 `userGender`，注入 `[STATE]`（「对方：男/女（指代时用他/她）」）让 LLM 用对人称。会话级（每通重判），不跨通话记忆。

### 5. 招呼语缓存

- 招呼语：`apps/server/src/persona/greetings.ts` 每人几句按人设写，预生成 TTS 按音色缓存（启动预热 + 落盘 `apps/server/.greetings-cache/`，重启零 TTS），接通随机放。磁盘缓存文件名带招呼语文本的 sha1 哈希——改了招呼语文本哈希即变、旧缓存自动失效（不再需要手动删目录），避免读到「改词前」的陈旧音频（如旧缓存里带时间词的招呼语）。招呼语 TTS 也带 `tailHint`（句尾自然落下），否则 CosyVoice 尾音平拖成金属音。
- 招呼语约定：开场白不能有"听到你的声音"这类已"听到用户"的意思（陪伴者先开口）。

### 6. 健壮性

- **LLM 超时**：DeepSeek `chat` 20s、`stream` 120s（`AbortSignal.timeout`），卡住不再无限挂、整条链卡死。
- **TTS 限流退避重试**：`synthesizeWithRetry`（`server.ts`）对 CosyVoice 实时 TTS 的 `RateQuota`/限流错误自动重试（最多 4 次，2s/4s/6s 指数退避）；被打断（`signal.aborted`）则静默退出、不重试。
- **NLS 心跳 + 重连**：哭/笑检测 WebSocket 静音时发心跳保活，断了 5s 自动重连、复用 token（`nlsSoundEvent.ts`）。
- **回声处理**：前端 `getUserMedia` 显式开 echoCancellation/noiseSuppression/autoGainControl；服务端 `onUserPcm` 在 `speaking` 时跳过（回声不进 ASR/声学/哭/附和），「用户在说话」改由 ASR 判到字驱动（不靠 RMS 阈值防底噪误判）。
- **打分与记忆召回并行**：`respond` 里 `planTurn`（打分）与 `recallContext`（召回+压缩，`assemble.ts` 拆出）用 `Promise.all` 并行，省掉一次串行等待，缩短「说完 → 开口」延迟；日志打 `[latency]` 记录耗时。`recallContext` 内部再把六个互不依赖的步骤（eager 召回 / 人物详情匹配 / 历史压缩 / 覆盖率 / 临近日期 / 人设增补）`Promise.all` 并行，各自 try/catch 降级，避免串行 await 时的延迟尖峰。

### 7. 关键教训

计时类逻辑的起点必须是「动作真正完成」（如播放完），不是「生成完」——用 `onPlaybackEnd` 这类真实完成回调，而非 `finally`/`await` 返回点。

### 8. 防重复问（`[ANSWERED]` 块）

实机暴露「已答过的问题被再问一遍」：用户答「暂时没有」，下一轮陪伴者又把同一个问题原样问一遍；「啊，是动漫的漫呀」整句重复两遍。根因是主动发话（`nudge`/`followup`）与被动回应（`respond`）没有共享「我问了什么、对方答没答」的状态。

- **状态**：`lastQuestionText` 记录上一轮问句原文，非问句结尾即清空；`/rtc/offer` 重置通话时清掉（避免上一通遗留问句污染新通话）。
- **注入**：当上一轮以问句结尾时，本轮生成 prompt 注入 `[ANSWERED]` 块（「你上一句问的是 X，对方正在答，严禁重问、严禁复述自己刚说过的话」），把「别再问」从软规则升级成强信号。
- **兜底**：`BLOCK_CONVERSATION` 与 `[TOPIC]` 换话题块也各带一条「别重复问已答问题」。

## 十一、好奇心：把「图补全」落成确定性逻辑（已落地）

> 核心：好奇心 = 「已知维度」vs「维度本体」的缺口检测——从已知往未知延伸，不是查户口。

### 本体（`brain/ontology.ts`）

十个维度，每个都**可有可无**（不是人人必填）：原生家庭 / 教育 / 职业 / 关系 / 爱好 / 重大事件 / 宠物 / 旅行 / 价值观 / 健康。

### 落库

- `memories` 表加 `dimension` + `aspect` 两列（fact / preference / episodic 归入某维度、再归该维度的某子槽；constraint / insight 不归）。
- `consolidateTurn` 抽取时顺带归维度 + 子槽（LLM 输出 `dimension` + `aspect`，`store.write` 落库）。
- `store.getCoverage(characterId, userId)`：按 dimension + aspect GROUP BY 数活跃事实。

### 缺口检测 + 注入（三级降噪）

- 每轮 `recallContext` 查 coverage → `buildCuriosityHint` 生成三级线索（已降噪，避免把模型当噪音忽略）：
  1. 完全空白（首次对话）→ 一条精简提示「你还不了解对方…一次只问一个，别查户口」，**不再一次性 dump 十个维度**；
  2. 空维度「还不太了解」最多列 3 个（多余用「等」收尾）；
  3. 部分了解的维度（**边级延伸**）：「你提到了原生家庭，但还不知道：父亲、兄弟姐妹」。
- `buildTurnMessages` 把 `[CURIOSITY]` 块塞进 user prompt（软信号）；`server.ts` 缓存本轮线索并打 `[CURIOSITY]` 日志（仅变化时），喂给 10s 静默找话题（`nudge`）让它优先补全了解盲区。
- 不硬指令、不查户口；情绪优先仍是「追唤醒高的点」——图缺口是候选池，不是命令。
- 存储先用 Postgres（节点/边落 `memories.dimension` + `aspect`），关系复杂到要多跳图遍历再迁 Neo4j。
