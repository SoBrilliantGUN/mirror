# 技术方案 · L6 角色卡结构化（具体实现）

> 从 `技术方案.md` §三 L6 行拆出。「**角色卡是唯一事实源**」是硬验收：代码里不再存第二份人物描述。

## 一、目标与边界

**要解决**：人物数据现在散在三处、靠人工保持一致——`character/<姓名>/`（角色卡）、`apps/server/src/persona/*.ts`（手抄 systemPrompt + 元数据）、`apps/client/app/companions.ts`（展示摘要）。L6 收敛成一处。

**L6 做什么**：

- 定 `Persona` 结构化 schema，所有机器字段收进角色卡 frontmatter。
- 写一个**构建期 codegen**：扫 `character/` → 生成结构化文件，server/client 各自 import。
- 生成物**不进 git**，构建/启动时生成。

**L6 不做什么**（边界）：

- 不改**按需详情**（认知/经历/偏好的语义匹配加载，运行期，保持不变）。
- 不引入 LLM 抽取——字段都是手工写进 frontmatter，没有需要"抽取"的散文。
- **删除 `关系.md`**：关系已由长期记忆的 `insight` 承载（已落地），L6 只负责不再读/拼它、删文件。

## 二、单一事实源：角色卡 frontmatter schema

每张 `角色卡.md` 顶部加 YAML frontmatter，正文（身份/原型蓝本/性格底色/说话方式/对话示例/红线/如何引导）**保持不变**，继续作 systemPrompt 原文。

```yaml
---
name: 程书衡
mbti: ESTJ          # 内部用，不对用户展示
gender: 男
temperament: 沉稳可靠，把乱麻理成清单          # → 前端卡片
profession: 项目总监
intro: 踏实、负责、执行力强的项目总监。重结果、重条理，把"清晰的步骤＋时间"当成给人安心的方式。……  # → 前端卡片
style: 语气沉稳有力、句子明确；爱说"我们先把事情排个序"。……                             # → 前端卡片
strength: 在你"事多到爆炸"时，帮你把一团乱麻排成一张清楚的清单。……                      # → 前端卡片
color: '#3e5a78'   # 头像底色 → 前端
rate: 1.15         # 语速基线 → TTS
voiceId: cheng-shu-heng   # 稳定逻辑名；真实 CosyVoice ID 走 .env 映射
voiceTint: ''      # 人设底色（暂空，等做 16 位时再定机制）
available: true    # 上线开关：只 4 位 true，其余 false
---
# 程书衡（ESTJ · 内部）   ← 标题保留，name/mbti 以 frontmatter 为准
…（正文不变）
```

字段按"谁消费"分两拨：

| 字段 | 类型 | 消费方 |
|---|---|---|
| name / mbti / gender | string | 两者（mbti 内部用） |
| rate / voiceTint / available | number / string / boolean | 服务端 `Persona` |
| voiceId | string（逻辑名） | 服务端（映射 env） |
| temperament / profession / intro / style / strength / color | string | 前端 `Companion` |

- `available` 要加进 `Persona` 类型（服务端拦截需要它）。
- 标题 `# 姓名（MBTI · 内部）` 与 frontmatter 可能重复；以 frontmatter 为准，标题仅作人类可读。

## 三、解析器（codegen）

- **手写确定性解析**（无第三方依赖）：frontmatter 行级 `key: value`（值取字面，内部标点照常）；正文、`记忆.md` 按原样取文本；不碰 LLM。
- **构建即校验**：缺必填字段、`mbti` 不在 16 型集合、`gender` ∉ {男,女}、`color` 非 hex、`available` 非布尔 → 抛错、构建失败。
- **systemPrompt 常驻底座组装**：`角色卡正文 + 【记忆索引】`（**不含关系**，关系已删）烤进生成文件。等价于把现有 `composePersonaPrompt` 从运行期上移到 codegen。
- 脚本：`scripts/gen-personas.ts`，`tsx` 跑（根已有 devDependency）。

## 四、生成物与消费方改造

codegen 一次产出**两个**文件（都 gitignore，都从同一份 `character/` 派生）：

1. `apps/server/src/persona/generated.ts` — `export const PERSONAS: Record<string, Persona>`（16 位，含 `available`）。
2. `apps/client/app/companions.generated.ts` — `export type Companion = {...}` + `export const COMPANIONS: Companion[]`（16 位）。

> 拆两份而非放 contracts：client 目前**不依赖** `@mirror/contracts`，Next 的 `next.config.mjs` 也没有 `transpilePackages`。拆两份避免给 client 引入跨包依赖与 Next 配置改动。两份由同一脚本同一源生成，单一事实源不因此打折。

**删除**：`apps/server/src/persona/{chengshuheng,shenzhiyao,shenyanqiu,sumingyue}.ts` 四个手抄文件、`apps/client/app/companions.ts`。

**contracts 改动**：`Persona` 类型加 `available: boolean`。

## 五、删除关系.md + loadPersona 瘦身

- 删除 16 份 `character/*/关系.md`。
- `loadPersona.ts` 只保留**按需详情**：读 `认知/经历/偏好`、`parseDetail`、`createPersonaMatcher`、`formatPersonaBlock`、`cosine`。
- 移除 `relationship` 字段、`composePersonaPrompt`（组装逻辑上移到 codegen）、`core`/`index` 的读取（改由生成物提供）。

## 六、上线拦截（available）

`resolvePersona` 改为**拒绝而非兜底**：

```ts
export function resolvePersona(name: string): Persona | null {
  const p = PERSONAS[name];
  if (!p || !p.available) return null;   // 未知 或 未上线 → 拒绝
  return p;
}
```

`server.ts` 对 `null` 回 4xx（原"未知名字静默兜底程书衡"废弃）。`available=false` 的 12 位：前端置灰 + 服务端直连 `/rtc/offer` 也打不开。

## 七、构建流水线（npm + Docker）

- 根 `package.json` 加 `"gen:personas": "tsx scripts/gen-personas.ts"`，`prestart`/`preclient` 前置它（`npm start`、`npm run client` 自动先生成）。
- `apps/client/package.json` 加 `predev`/`prebuild`（`tsx ../../scripts/gen-personas.ts`），直跑 `npm run dev/build -w @mirror/client` 也自动先生成。
- `.gitignore` 加 `apps/server/src/persona/generated.ts` 与 `apps/client/app/companions.generated.ts`。
- **Docker**：`Dockerfile.server` / `Dockerfile.client` 都 `COPY character/` 并在 build 前跑 `gen:personas`（生成物不进 git，镜像内现生成）。
  - ⚠️ `.dockerignore` **不能排除 `character/`**：构建期 codegen 要读它，server 运行期的 `loadPersonaDetails`（按需详情）也要读它——`COPY character character` 一次满足两处。之前 `.dockerignore` 有 `character/` 会导致 `docker compose up --build` 在 COPY 那步报「file not found」，已移除。

## 八、落地顺序

1. 程书衡加 frontmatter → 写 codegen + 两个生成物 + server/client 改造 → 端到端跑通一位。
2. 其余 15 位补 frontmatter、删各自 `关系.md` → 全量生成、构建校验通过。
3. `available` 只 4 位 true → 验证前端置灰 + 服务端拦截。

## 九、实现时定的小细节

- voiceId 逻辑名 → env key 的映射：保留现有 `VOICE_ENV_KEY`（从 persona/index.ts 迁到一处小配置），真实 CosyVoice ID 仍走 `.env`。
- frontmatter 值取字面（无需引号包裹，内部中文引号/逗号照常）；`color` 写裸 hex 不带引号；解析按「首个冒号」拆 `key: value`。
- 标题 `# 姓名（MBTI · 内部）` 与 frontmatter 的 name/mbti 一致性，纳入 codegen 校验（不一致报错）。
