# 技术方案 · L2 语音流水线（具体实现）

> 从 `技术方案.md` §三 L2 行拆出。「情绪靠声音承载 = 真」是硬验收。

## 一、选型（已定）

| 项 | 决定 | 为什么 |
|---|---|---|
| TTS | 阿里云百炼 CosyVoice（`cosyvoice-v3.5-plus` + 声音设计音色） | 指令式情绪（独立 `instruction` 字段）、中文强 |
| ASR | 阿里云百炼 Paraformer 实时 | 流式 + interim、中文强、与 TTS 同源一个 key |

**被否掉的**：ElevenLabs（英文强、无原生情绪控制）、MiniMax（只有基本情绪 happy/sad/angry）、硅基流动 CosyVoice2（`<|endofprompt|>` 在输入里不生效，指令被念出来）。

## 二、情绪框架（离线验真已通过）

情绪 = **通用镜像 + 人设底色**（两层，通用框架，不绑任何一位陪伴者）：

| 层 | 谁决定 | 内容 |
|---|---|---|
| ① 通用镜像（16 位共用） | 对方 affect | 开心→`warm`、悲伤→`tender`、激动→`steady`、平常→`natural` |
| ② 人设底色（每位不同） | 角色卡 `voiceTint` | 这个陪伴者表达情绪时的语气修饰 |

### 4 方向映射（已验真，代码 `emotionInstruction.ts`）

| 方向 | 触发（对方状态） | 指令 | prosody |
|---|---|---|---|
| `warm` 开心 | valence > 0.25 | 非常温暖轻快明快带笑意 | rate 1.05 / pitch 1.05 |
| `tender` 悲伤 | valence < -0.25 且唤醒低 | 非常温柔轻柔心疼共情 | rate 0.9 |
| `steady` 激动 | valence < -0.25 且唤醒高 | 沉稳镇定安抚给确定感 | rate 0.85 |
| `natural` 平常 | 其它 | 轻松自然口语化像聊天 | — |

### 音色（声音设计）

- 每位陪伴者一个音色（不能共用一张嘴）：`voice_id` 存 `.env`，映射见 `persona/index.ts` 的 `VOICE_ENV_KEY` —— `COSYVOICE_VOICE`（程书衡）/ `COSYVOICE_VOICE_SZY`（沈知遥）/ `COSYVOICE_VOICE_SYQ`（沈砚秋）/ `COSYVOICE_VOICE_SMY`（苏明悦）。
- 音色由 `voice_prompt` 文字描述生成（`npm run enroll-voices`，`target_model=cosyvoice-v3.5-plus`）；未配专属音色时回落程书衡音色（`server.ts` 会 warn）。

## 三、实时方案（已跑通）

### 架构

```
浏览器 (L0)
  麦克风 → Opus 编码 → WebRTC 上行
  WebRTC 下行 → Opus 解码 → 播放
  前端 VAD（能量检测）→「你开口」→ 打断信号（data channel）

服务端 (werift，纯 TS)
  收 Opus → 解码 PCM（16kHz）→ onUserPcm 分流：
    ├─ Paraformer 实时 ASR → 文本
    ├─ AcousticFeatureExtractor → 副语言 z-score（响度/音高/语速/停顿）
    ├─ NlsSoundEventDetector → NLS 云端哭/笑事件（零本地模型）
    └─ BackchannelEngine → 停顿处轻声附和
  文本 / 哭事件 → L3 大脑 → 回复（按句切分）
  逐句 → CosyVoice 实时 TTS → PCM → 编码 Opus → WebRTC 下行
  收到打断信号 → 立刻停声（abort TTS + 清播放队列）
```

### 关键 API（已查实）

- TTS + ASR **同一个 WebSocket 端点**：`wss://{WorkspaceId}.cn-beijing.maas.aliyuncs.com/api-ws/v1/inference`，Bearer 鉴权。
- **TTS**（CosyVoice 实时）：`run-task` → `continue-task`（发文本）→ `finish-task`，二进制 PCM 返回；参数含 `voice` / `format` / `sample_rate` / `rate` / `pitch`。
- **ASR**（Paraformer 实时）：`run-task` → 发二进制 PCM → `result-generated`（含 interim）→ `finish-task`；参数 `format=pcm`、`semantic_punctuation_enabled=false`（VAD 断句，低延迟）。

### 打断 = 立刻停声

回复按句切分、逐句 TTS；收到打断信令 → `currentAbort.abort()` 中止当前句合成 + `rtc.clear()` 清空播放队列，**立刻停声**（不是「播完当前句再停」），后续句不再合成。

### 组件

- **L0 前端**（Next.js）：`getUserMedia` 采集 → werift 连 → 播放 + 前端 VAD 打断。
- **L1**（werift）：服务端当 WebRTC peer，收/发 Opus + data channel 承载打断信令。
- **L2 适配器**：`ParaformerRealtimeASR` + `CosyVoiceRealtimeTTS`（WebSocket 流式）。

## 四、副语言特征 + 非言语发声（已实现）

两条「情绪靠声音承载」的声音信号，都在服务端 `onUserPcm`（16kHz PCM 咽喉点）接入，不碰浏览器、不加 data channel。

### 副语言特征 `AcousticFeatureExtractor`（`speech/acousticFeatures.ts`）

- 流式喂 16kHz PCM，按 20ms 帧算：响度（RMS→dB）、音高（`pitchfinder` YIN，40ms 滑窗、仅 voiced 帧）、静音占比。
- 回合结束 `finalize(text)` 出四个 z-score：`rateZ`（字数/时长）、`pitchZ`、`loudnessZ`、`pauseZ`。
- **z-score 基线**：会话内最近 N 轮 raw 值的 mean+std（`BASELINE_KEEP=32`），冷启动（<2 样本）回 0。每通电话 `new` 一个实例 → 基线自动按通话隔离。
- 语速需要 ASR 文本，所以放在服务端（原方案 L0 前端拿不到「字数」）；纯哭无字时 `rateZ` 置 0、不更新 rate 基线。

### 非言语发声 `NlsSoundEventDetector`（`speech/nlsSoundEvent.ts`）

- 只做哭/笑，不做叹气（歧义大，见 `docs/心理学依据/非言语发声检测.md`）。
- **云端，零本地模型**：阿里云智能语音交互（NLS）「声音事件检测」，`wss://nls-gateway-cn-shanghai.aliyuncs.com/ws/v1`，namespace `AudioEventDetection`。实时 16kHz PCM 流式上行，回 `Cry` / `Laughter` / Music / Knock 等事件 + 起止时间 + 置信度。
- **鉴权**：NLS 项目 AppKey + 阿里云 AccessKey（`CreateToken` HMAC-SHA1 签名换 token），**不是**百炼的 DashScope key。也可直接配 `NLS_ACCESS_TOKEN`（`nlsToken`，已拿好的 token）跳过 CreateToken。未配凭证时优雅降级（不发事件，主链路照常）。
- **协议**：`NlsSoundEventDetector` 连 WS → 发 `StartDetection` 命令（JSON 文本帧）→ 二进制帧喂 PCM → 收 `TaskResult`，把 `event_type=Cry→cry`、`Laughter→laugh` 喂进打分。
- **降级**：拿不到 token / 连不上 / 鉴权失败只记日志、不发事件，主链路照常。
- 部署：纯 Node，无额外进程。凭证走 `.env` 的 `NLS_APPKEY` / `NLS_ACCESS_TOKEN`（直传 token，优先）或 `NLS_ACCESS_KEY_ID` / `NLS_ACCESS_KEY_SECRET`（走 CreateToken 现拿）。

> **为什么不用本地模型**：最初想用 PANNs CNN14，但 Zenodo 权重 1.3GB、魔搭纯权重 ~358MB + torch 环境 ~1.7GB，本地磁盘吃紧；改用 NLS 云端声音事件检测，零本地下载、还自带 Cry/Laughter 两类 + 时间戳。

### 触发（`server.ts`）

- **有字**：ASR final → `respond(text, vocalizations)`，这期间攒的哭/笑事件一并附着进打分。
- **纯哭无字**：哭事件连击结束 3s（去抖）→ `respond('', vocalizations)`，陪伴者主动温柔回应；持续不停最多 6s 强制回应一次，两次回应间 8s 冷却（`server.ts` 的 `VOCAL_DEBOUNCE_MS / VOCAL_MAX_HOLD_MS / VOCAL_COOLDOWN_MS`）。
- 空文字时打分/生成 prompt 的「她这一轮」写成 `（没有说话，只是哭）`，避免空 prompt（`brain/prompts.ts` 的 `formatUserTurn`）。

### 哭/笑聚合加权 → 主导类型（`speech/vocalEvents.ts`）

NLS 对哭/笑会互相误判（纯哭偶尔吐 laugh、纯笑偶尔吐 cry），且单点置信度偏低。`VocalEventAggregator` 聚合一轮内的事件，用 confidence 加权求和判「主导类型」：

- 低置信度（< `confThreshold` 0.3）直接丢弃；cry / laugh 各自累加 confidence。
- `dominant()`：加权和较大一方、且差距超过 ratio（1.15）才判定为 `cry` / `laugh`，否则 `null`（不确定）。
- `dominantVocal` 确定性覆盖 `decideEmotion`（`brain/decide.ts`）：哭→`tender`（心疼安慰）、笑→`warm`（一起开心），**优先于通用镜像**——「哭/笑」是强于「效价/唤醒」的硬信号，直接决定这一轮 TTS 的情绪方向。

## 五、逐句情绪（B2，生成后分类）

`emotion`（turn 级）细到句级：多句回复能「一句暖、一句稳」。

- `brain/segmentEmotion.ts`：`classifySegmentEmotion` 生成后对每个 segment 跑一次轻量分类（温度 0、只出一个标签），失败回退本轮基调。
- **首句零延迟**：首句直接用 `plan.emotion`（`decideEmotion` 已给出本轮基调），第 2 句起才分类（与上一句播放重叠，不伤首字延迟）。
- `TurnResult.segmentEmotions?`：与 `segments` 等长；TTS 逐句用各自的 `instruction` + `EMOTION_PROSODY`（逐句取 rate/pitch）。
- **句尾处理 `tailHint`**：`emotionInstruction.ts` 的 `tailHint(text)` 按句末标点追加一句 prosody 提示——问句→「句尾轻轻上扬，像真的在等回答」、感叹句→「语气加重、句尾稳而有力」、陈述句→「句尾自然落下，不要上扬」；叠加在 base 指令后，让逐句有起伏、不匀速念稿（`server.ts` 在 `buildInstruction` 后拼上它）。

## 六、副语言 backchannel / 附和（B3）

用户长段倾诉时，教练在自然停顿处轻声插一句「嗯 / 对 / 然后呢」，给「被听见感」不打断。

- `speech/backchannel.ts`：`BackchannelEngine` 在 `onUserPcm` 单点做静音检测（RMS 阈值，同副语言），配合 ASR interim（说到一半）判定「停顿」。
- **触发**：interim 有字 + 连续静音 ≥ `silenceMs`(500) + 冷却 15s + 每 turn ≤6 次 + 本 turn 已连续说满 `minSpeechMs`(30s) 才允许插嘴（`server.ts` 实例化时传的 `{ silenceMs:500, cooldownMs:15000, maxPerTurn:6, minSpeechMs:30000, gain:0.5 }`）。
- **片段**：预生成缓存（懒、按音色），`streamTTS` 出 24kHz PCM，`BACKCHANNEL_PHRASES`（「对 / 然后呢 / 我在听」）+ 轻声指令；第一版只覆盖已上线 4 位（`VOICE_ENV_KEY`）。
- **鸭音**：`rtc.pushAgentPcm(pcm, gain)` 加 gain 参数（默认 0.5），在重采样后的新数组上做、不污染缓存片段。
- **让位**：用户接着说（前端 VAD 边沿）→ `onInterrupt` → `rtc.clear()` 清掉残余「嗯」+ `backchannel.reset()`。
