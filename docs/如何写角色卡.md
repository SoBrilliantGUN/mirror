# 如何写角色卡（本项目实操指南）

> 本文是给本项目 16 位「陪伴者」写角色卡的统一方法与模板。
> 一句话定位：**角色卡是写给 AI 的「人物说明书」——它决定 AI 用谁的声音、怎么想、怎么说话、怎么反应。**
> 本文综合了 AI 角色卡教程（Character.AI、SillyTavern/tavern-cards、中文角色扮演教程）与人物小传（传记）写作方法的共识，并针对本产品做了裁剪。

---

## 一、角色卡是什么

角色卡（Character Card）本质是**人物的"出厂设定"**：姓名、身份、性格、说话方式、背景故事、行为边界。模型读它，就知道"我现在是谁"。

- **写多了** → 提示词臃肿、注意力稀释、AI 只抓住重复最多的几个词，人物变"纸片"
- **写少了** → 人物立不住，每次回答都漂移、OOC（out of character）
- 核心矛盾：**既要细节丰富让人设稳定，又要简洁省 token**。解法是——**结构化、只写有效信息、用"特征"而不是"形容词"**。

---

## 二、本项目的关键变化

**变化 1：随机 → 真实人物蓝本**

- **旧方案**：人物 = 性格标签 + 从「职业池 / 爱好 / 习惯」里**随机抽取**，拼出一个"活人"。
- **新方案**：随机机制作废。每位陪伴者都锚定一位**真实存在的、同 MBTI 的知名人物**作为蓝本，把职业、人生片段、说话语气、价值观、小癖好等"血肉"进角色卡。

**变化 2：单文件 → 文件夹 + 渐进式加载**

- **旧方案**：一个人一个 `.md` 文件，全部内容一股脑塞进系统提示词。
- **新方案**：一个人一个**文件夹**（`character/{{姓名}}/`），内部按"**是否常驻**"拆成 4 个文件：**核心卡常驻加载**，**认知 / 经历 / 偏好**三个渐进模块**按场景触发加载**——像 skills 一样，用到了才加载，上下文不撑爆，人设也立得住。

> 注意：蓝本是**取材的参照**，不是直接扮演真人。角色仍用虚构名字，内在"肌理"取自真人；**绝不对用户明示**原型是谁、MBTI 是什么（见产品方案系统 4）。

## 三、目录结构（一个人一个文件夹）

```
character/
├── README.md               # 结构说明 + 渐进式加载机制
├── 顾承安/                  # 一位陪伴者一个文件夹
│   ├── 角色卡.md            # 核心人设（常驻，始终注入）
│   ├── 记忆.md              # 记忆索引/目录（常驻，始终注入）—— 一行一条：标题 + 触发钩子 + 链接
│   ├── 认知/                # 世界观条目，一条一个文件（命中触发才加载）
│   │   ├── 慢慢变富.md
│   │   └── …
│   ├── 经历/                # 人物小传 + 人生片段，一条一个文件（命中触发才加载）
│   │   ├── 人物小传.md
│   │   └── …
│   └── 偏好/                # 习惯/口味/怪癖，一条一个文件（命中触发才加载）
│       └── …
├── 苏念安/
└── …（共 16 个文件夹）
```

**分层原则（像 Claude 的记忆：目录 + 分开的详情文件）**：

| 层 | 文件 | 加载方式 | 放什么 |
|---|---|---|---|
| 核心层（常驻） | `角色卡.md` | 始终注入 | 身份、性格矛盾、说话方式、对话示例、红线、如何引导 |
| 索引层（常驻） | `记忆.md` | 始终注入 | 所有渐进条目的「标题 + 一句话钩子 + 链接」，不写详情 |
| 详情层（按需） | `认知/*.md` `经历/*.md` `偏好/*.md` | 命中触发才加载 | 每条一个文件，写具体内容 |

**关键**：`记忆.md` 是常驻的"目录"，只记录"有哪些细节、什么时候该想起来"，不装细节本身；`认知/经历/偏好` 下的每个文件才装一条细节。命中触发时，按索引里的链接去加载对应详情文件——上下文不撑爆，细节也立得住。

**另外**：
- 每位陪伴者还有一个常驻的 `关系.md`（记录「用户 ↔ 此位陪伴者」的关系，**每位独立、不混用**——跟 A 的关系和跟 B 的关系是两回事）。
- 「用户」本身也按同样的结构放在根目录 `user/`：核心卡 `用户画像.md` + 索引 `记忆.md` + `认知/经历/偏好/情绪/` 渐进详情（用户的世界观/经历/偏好/情绪轨迹）。

## 四、角色卡模板

### 4.1 核心卡 `角色卡.md`（常驻，始终注入）

```markdown
# {{姓名}}（{{MBTI}} · 内部）

> 常驻核心卡，始终注入上下文。认知/经历/偏好见同目录渐进模块，按场景触发加载。

## 身份
{{一句话：气质 + 写死的职业}}

## 原型蓝本
- 真实人物：{{名字}}
- 借鉴血肉：{{职业 / 语气 / 价值观 / 细节，各一句}}

## 性格底色（矛盾建模）
- 表层：{{2~3 条，别人第一眼看到的样子}}
- 深层：{{2~3 条 "X vs Y" 的拉扯，不贴标签}}

## 说话方式
{{语速 / 句式 / 口头禅 / 语气词，具体到字面，要能"听见"这个人}}

## 对话示例
{{2 段，跨情绪档位，严格遵循"先接住情绪 → 映照内心 → 引导一步 → 落回当下"}}

## 红线
- {{否定 + 缘由 + 正向替代}}

## 如何引导你
{{本型专属的成长抓手}}
```

**核心卡必须"自足"**：光靠这一张卡，TA 就要能在大多数回合里立得住人设。所以身份、性格矛盾、说话方式、红线、对话示例必须都在核心卡里；细节背景才放到渐进模块。

### 4.2 记忆索引 `记忆.md`（常驻，像 MEMORY.md 的目录）

`记忆.md` 是常驻的"目录"，只存「标题 + 一句话钩子 + 链接」，不写详情：

```markdown
# {{姓名}} · 记忆索引

> 常驻目录，始终注入。每条只存标题 + 触发钩子 + 链接；命中触发时才按链接加载对应详情文件。

## 认知
- [慢慢变富](认知/慢慢变富.md) — 不信风口、守住本金；触发于聊投资/赚钱/焦虑

## 经历
- [人物小传](经历/人物小传.md) — 他如何长成现在这样；触发于聊过去/成长

## 偏好
- [旧钢笔和小本子](偏好/旧钢笔和小本子.md) — 记重要的事；触发于聊文具/记录
```

### 4.3 详情文件 `认知/` `经历/` `偏好/`（按需，一条一个文件）

每个渐进条目是一个独立文件，frontmatter 声明「内容概要 + 触发场景」，正文写详情：

```markdown
---
name: 慢慢变富
description: 触发于聊投资、赚钱、暴富、风口、急于求成
type: 认知
---
他见过太多"一夜暴富又一夜归零"的人，于是只信"慢慢变富"。快钱里往往藏着快亏，能守住本金、走得很久的，才真正赢。
```

- `name`：条目名（也用作索引链接的锚点）
- `description`：一句话，写清"当对话触及什么时加载"（供运行时匹配）
- `type`：认知 / 经历 / 偏好

## 五、人物小传（`经历.md` 的开头，叙事性）

### 5.1 人物小传是什么

人物小传是传记的一种，**用简短叙事讲清"这个人是怎样长成现在这样的"**。它是角色卡里最"讲故事"的部分，给模型一个**因果链**——为什么 TA 会这样想、这样说、这样怕。

### 5.2 写法要点（传记写作共识）

1. **真与细**：真实是底线，细节是血肉。宁要一个真实的、能被记住的细节，不要一堆正确的空话。
2. **用具体事件代替概括**——写性格成因，不直接论断：
   - ❌ "他从小热爱文学，工作认真负责"
   - ✅ "年轻时亲眼见过别人在风口里一夜暴富又一夜归零，从此只信'慢慢变富'"
3. **叙行录言**：选取最典型、最能体现性格的**行动和语言**来写，让人物"自行"展现，而非作者下结论。
4. **埋记忆钩子**：留 1 个"可触发的细节"（一件旧物、一个习惯、一句反复说的话），用户哪天提到，TA 能自然呼应——这也是渐进加载的触发源。
5. **时间顺序 + 突出重点**：按时间线索走，关键转折详写、次要略写、平淡不写；篇幅控制在 120~180 字。

### 5.3 人物小传的落点

人物小传是 `经历/人物小传.md` 这个详情文件，**不常驻**，只在对话触及"过去、成长、家庭、职业转折、价值观形成"等场景时、由 `记忆.md` 里的链接加载。它和核心卡里的"性格矛盾"互为表里：核心卡给"是什么"，小传给"为什么"。

## 六、渐进式加载机制

### 6.1 为什么需要

完整角色卡（职业+背景+认知+偏好+说话+示例）可达 2000~4000 token。若全部常驻，叠加系统提示词 + 对话历史，上下文很快被撑爆，且注意力被稀释（AI 只抓重复最多的词）。

### 6.2 怎么分层（像 Claude 的记忆）

- **核心卡 `角色卡.md`（常驻）**：身份 + 性格矛盾 + 说话方式 + 红线 + 对话示例 + 如何引导。~800 token，够 TA 在大多数回合立住人设。
- **记忆索引 `记忆.md`（常驻）**：只存「标题 + 触发钩子 + 链接」的一行行目录，让运行时知道"有哪些细节、何时该想起来"，成本极低。
- **详情文件 `认知/` `经历/` `偏好/`（按需）**：一条一个文件。**命中索引里的触发钩子，才按链接加载对应详情文件；话题离开即卸载**——这正是 Claude 记忆（目录 + 分开的详情文件）/ skills / lorebook 的思路。

### 6.3 触发怎么设计

每条详情文件的 `description` 里写清"当对话触及什么时加载"，供运行时匹配：

1. **触发场景**（语义）：如"用户聊到投资、亏钱、失败、风险、后悔"。
2. **关键词**（词面）：如"钱、亏、风口、风险、后悔"。

`记忆.md` 里的一行钩子，就是这条 `description` 的浓缩。运行时先扫 `记忆.md`（它常驻、很小），命中某条的钩子，再按链接加载详情文件；话题切换后回收，保持上下文精简。

### 6.4 硬约束

- **核心卡自足**：拆走渐进模块后，核心卡仍能独立撑住人设。
- **条目之间不冲突**：渐进条目只"补细节"，不得与核心卡、与蓝本、与已有条目相矛盾（详见第八节）。
- **同一场景可同时命中多条**：多条命中时按文件内顺序注入即可。

## 七、写作原则（把"架空"变成"血肉"）

### 1. 只写"特征"，不写"美"
外貌/细节的判断标准只有一条：**遮住名字，能不能只靠这些特征认出是谁？**
- ✅ 写：能被记住的细节（"左手食指和中指有弹吉他磨出的茧""口袋里永远揣着一支钢笔"）
- ❌ 不写：AI 默认值（黑发黑眼）、万能美人描写（精致、白皙、好看）、五官逐件报账

### 2. 背景只写"造成影响"的关键事件
自查标准：**删掉这条，这个人会不会变？不会，就删。** 不要列人生年表。

### 3. 性格用"矛盾建模"，别贴标签
写"温柔""毒舌"这类标签，AI 会直接套用刻板印象，变成伪人。正确做法是写**互相拉扯的矛盾**：
- ❌ "他温柔体贴"
- ✅ "他习惯把别人的难处都扛下来，却从不肯承认自己也会累——温柔是他的铠甲，也是他的软肋"

### 4. 否定句是"粉红大象"——写红线必须"三件套"
只写"不要 XX"，AI 反而会拐回去。每条红线必须：**否定 + 缘由 + 正向替代**：
- ❌ "禁止嘴上说自己长大了"
- ✅ "禁止用'我已经成熟了'证明成长——她的成长体现在用行动默默扛事，而不是口头宣告"

### 5. 对话示例 = 最便宜的人设锚点
模型从**示例对话**学到的"声音、节奏、长度"，比任何形容词都管用。每个角色给 2 段，跨不同情绪档位（轻松 / 低落），每段末尾写 `——对话结束——`。

### 6. 重复即加权，细节会变成"复读素材"
口头禅、推眼镜这类小动作**只写一次**、**只在合适场景出现**。写多了，AI 就只剩这一面。

### 7. 用"你"指代角色
所有指令与描述用第二人称"你"，让模型直接代入："你是一个……的人，说话……"

## 八、一致性约束（底座不可推翻，只可补软细节）

角色卡里写定的内容**不可推翻**，只可"补软细节"：

- 职业、价值观、关键经历、红线、说话方式 = **底座**，是唯一事实源，对话中**不得被改写**
- 陪伴者可在底座之外补软细节（爱好/口味/小回忆/习惯），但**一经说出就永久固化、强制一致**——不前后矛盾、不改口，避免被用户说"你变了"
- 例如蓝本是"外科医生"，就不会后来说"我从小就晕血"

## 十、与产品其他约束的关系

角色卡只决定**"语气与底色"**，不改动产品的最高优先级：

1. **对话内核（最高优先级）**：先接住情绪 → 映照内心 → 引导一步 → 落回当下。角色卡里的"说话方式"要服从这个节奏。
2. **安全底线（P0）**：自伤/轻生信号时，角色必须切回"强制转介"，蓝本性格不得凌驾于安全红线之上。
3. **身份诚实**：无论蓝本多像真人，AI 仍是 AI，不假装是人、不承诺现实做不到的事。
