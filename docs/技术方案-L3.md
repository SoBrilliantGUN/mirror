# 技术方案 · L3 对话大脑（具体实现）

> 从 `技术方案.md` §三 L3 行拆出。地基三拍：**两次调用**（打分/生成分离）、**后端判 mode**（代码硬执行阈值，不交给 LLM）、**LLM 融合打分**（call1 同时读文本 + 副语言 z-score）。

## 一、一条 turn 的时序

```
你说完（VAD 判定 utterance 结束）——或只哭不说话（哭事件连击结束 1.2s 去抖）
 → 副语言特征（z-score）+ ASR 文本 + 哭/笑事件  同时到
 → L4 安全检测（并行、独立、前置）
 → call1 打分（非流式 ~300ms，出 affect；融合 副语言 + 哭/笑事件）
 → 后端 decideMode + emotion + stance + voiceConfig（微秒）
 → call2 生成（流式，mode/stance 已烤进 prompt）
 → call2 出纯文本 → 逐句 TTS（voiceId + voiceConfig + emotion 指令）
 → 播放中你开口 → L0 VAD 打断 → 停 TTS 流
```

## 二、数据契约（进 `packages/contracts`）

```ts
// —— call1 打分输出 ——
type Affect = {
  valence: number;        // -2..+2
  arousal: number;        // -2..+2
  dominance: number;      // -2..+2
  incongruence: boolean;  // 文字平静 + 声音异常 = 逞强
};

type Mode = 'casual' | 'careful';
type Stance = 'guide' | 'accompany';   // 由支配度驱动：低支配 → 只陪不抛清单

// —— 表达「陪伴者此刻情绪」的标签，喂给 TTS ——
// 4 个方向，由对方情绪驱动（通用镜像），再叠加人设底色 voiceTint。
type EmotionTag = 'warm' | 'tender' | 'steady' | 'natural';

type VoiceConfig = {
  speed: number;      // 语速倍率 0.7~1.1
  energy: number;     // 能量/响度 0.7~1.1
  pauseMore: boolean; // careful 模式句间停顿更长
};

type SafetyAction = { level: 0 | 1 | 2; action: 'none' | 'refer' };

// —— L3 对外接口返回值 ——
type TurnResult = {
  affect: Affect;
  mode: Mode;
  stance: Stance;
  emotion: EmotionTag;      // 本轮回应情绪（由对方情绪驱动）
  voiceConfig: VoiceConfig;
  segments: string[];       // 已按句切分
  safetyAction: SafetyAction;
};
```

> **音色（voiceId）与人设底色（voiceTint）都不放 VoiceConfig**：它们都是「加载的是谁」的固定身份，属于 `Persona`（L6）。TTS 调用时合并 `speak(text, { voiceId: persona.voiceId, ...voiceConfig, instruction: buildInstruction(emotion, persona.voiceTint) })`。

## 三、call1 打分（非流式，小输出）

**system prompt 结构**：
1. 角色声明：你是情绪评分器，只输出 JSON，不聊天、不解释。
2. 三维定义 + 锚点（照抄产品方案的 -2..+2 定义表）。
3. 副语言阅读规则：声音特征以「相对她基线的 σ 值」附在文本后，融合进打分。
4. incongruence 判定规则：文字效价接近中性（平静）但声音 z-score 明显偏「高唤醒」方向（语速↑/响度↑/音高↑/停顿↓）→ `true`。
5. 输出格式：严格 JSON。

**user 注入**（每轮拼）：`【她这一轮】`（空文字时兜底成「没有说话，只是哭」，见 `formatUserTurn`）+ `【最近对话】6 轮` + `【声音特征】语速/音高/响度/停顿 z-score` + `【非言语发声】哭/笑事件（有才加）` + `【当前心境轨迹】mood 最近 3 个 EMA 点`。

**输出**：`{ valence, arousal, dominance, incongruence }`（约 30 token）。

## 四、后端判 mode / stance / emotion / voiceConfig（纯代码，可单测）

```ts
function decideMode(a: Affect, s: SafetyAction): Mode {
  if (s.level >= 1) return 'careful';
  if (a.valence < -0.25) return 'careful';
  if (a.valence < 0 && a.arousal > 0.4 && a.dominance < 0) return 'careful';
  if (a.incongruence) return 'careful';
  return 'casual';
}
// 退出 careful 需连续 2 轮平稳（防抖，放 L5 状态机）

const stance = a.dominance < 0 ? 'accompany' : 'guide';

const base = mode === 'careful'
  ? { speed: 0.78, energy: 0.82 }
  : { speed: 1.0,  energy: 1.0 };
const speed = base.speed * (1 - 0.10 * clamp(a.arousal, 0, 2) / 2); // 唤醒越高越放慢

// 通用镜像：由对方情绪（affect）决定回应方向，所有陪伴者共用。
function decideEmotion(a: Affect): EmotionTag {
  if (a.valence > 0.25) return 'warm';            // 开心 → 轻快温暖
  if (a.valence < -0.25) {
    return a.arousal > 0.4 ? 'steady' : 'tender'; // 激动→安抚 / 悲伤→心疼
  }
  return 'natural';                               // 平常 → 自然
}
```

**情绪映射 = 通用镜像 + 人设底色（两层，通用框架）**：

| 层 | 谁决定 | 内容 |
|---|---|---|
| ① 通用镜像（16 位共用） | 对方的 affect | 开心→`warm` 轻快温暖；悲伤→`tender` 温柔心疼；激动→`steady` 沉稳安抚；平常→`natural` 自然 |
| ② 人设底色（每位不同） | 各自角色卡的 `voiceTint` | 这个陪伴者表达情绪时的语气修饰，叠加在方向指令后 |

> TTS 指令 = `buildInstruction(emotion, persona.voiceTint)` = 方向指令 + 「，」+ 底色。情绪由对方的情绪驱动（镜映/同频），人设只在上面做幅度微调；`voiceTint` 是每个陪伴者自己的，不硬编码在框架里。

## 五、call2 生成（流式）

**system prompt 分块**（优先级递减）：

| 块 | 内容 | 动态 |
|---|---|---|
| ① 对话内核（最高） | 四步情感节奏 + 不迎合 + 判断标准 | 固定 |
| ② 安全底线（最高） | 自伤/轻生 → 先托住再强制转介 | 固定 |
| ③ 身份与边界 | AI 诚实 / 不越界 / 承认理解有限 / 转专业 | 固定 |
| ④ 当前模式 | careful 或 casual 指令块（本轮 mode） | 动态注入 |
| ⑤ 本轮 stance | accompany：只陪不抛清单；guide：可给步骤+时间 | 动态注入 |
| ⑥ 人物（角色卡） | 角色卡底座（身份/底色/说话方式/破绽/红线） | 固定 |
| ⑦ 回复风格 | 1~3 句、口语化、情绪用声音承载、共情要具体 | 固定 |

**user**：最近 N 轮 + 本轮文本。

**输出**：纯文本流式。后端按句切分（句末标点后切）；情绪不在此处决定（已由后端 `decideEmotion` 从 affect 推导）。

> system prompt 里加一条格式指令：直接输出回复文本，1~3 句口语化短句，不要情绪标签、不要编号、不要解释、不要括号舞台提示、不要 emoji。

## 六、Life Coach 改造：Frame 状态机 + GROW（朋友 ⇄ 教练）

> 补上「引路人」那一半。新增一个与 `Mode`（情绪强度）**正交**的维度 `Frame`（交互框架）：
> `friend` = 陪伴/映照；`coach` = GROW 成长引导。两者叠加：教练态里照样有情绪强度（她低落时先接住，不硬推 GROW）。
>
> 落地：`brain/coach.ts`（`classifyCoachCue` + `CoachTracker`）、`brain/consolidate/goalTurn.ts`（后台课题巩固）、
> `store/goals.ts` + `db.ts` 的 `growth_goals` 表、`prompts.ts` 的 `BLOCK_COACH/BLOCK_COACH_INVITE/BLOCK_CELEBRATE`、
> `context.ts` 的 `formatGoalBlock`/`buildGoalFollowUpHint`（`[GOAL]`/`[FOLLOW_UP]` 块）。

### 6.1 数据契约（`packages/contracts`）

```ts
type Frame = 'friend' | 'coach';
type CoachCue = { explicit: boolean; invite: boolean; resolved: boolean; theme: string | null };
type GrowthStage = 'goal' | 'reality' | 'options' | 'will' | 'done';
type GrowthGoal = { /* title + goal/reality/options/will + stage + progressNote + status active/done/archived + lastReviewedAt */ };
```

### 6.2 状态机（`CoachTracker`，会话级、每通重置，仿 `ModeTracker`）

```
朋友态（默认）
  ├─ ① 用户明说求助（explicit：「我该怎么办」「我到底想要什么」「好迷茫」）→ 立即进教练
  └─ ② 主动察觉（invite：反复说累/纠结/走不出来，连续 ≥2 轮）→ 注入 [INVITE] 温柔邀入 → 接话进 / 不接退回陪伴
教练态（进了待到挂断）
  └─ ③ 解决/放下（resolved：「我做到了」「解决了」「我想通了」「算了」）→ 退回朋友 + 注入庆祝块 + 课题标记 done
```

- 教练意图每轮由 `classifyCoachCue`（LLM，仿 farewell，temperature 0）判定，与打分/安全/道别**并行**。
- 切换打日志：`[coach] 进入教练模式（用户明说求助|主动察觉·用户接话），课题「…」` / `[coach] 退出教练模式（对方已解决/放下），回到朋友态`。

### 6.3 GROW 怎么落（重骨架 + 轻表达）

- **重骨架**：`growth_goals` 表存 `title / goal(G) / reality(R) / options(O) / will(W) / stage / progress_note / last_reviewed_at`，生命周期 `active → done → archived`，跨通话持久（按 `persona_name + user_id` 隔离）。
- **轻表达**：`[GOAL]` 块只把进度喂给模型，模型用自己的语气化进对话，绝不念档案、不填表。
- **后台巩固** `consolidateGoal`（coach 轮后异步、不进热路径）：抽取/推进 GROW 字段、检测 `done`（庆祝收尾）/`archive`（放下归档），写 `growth_goals`。

### 6.4 朋友态 vs 教练态 行为边界

> 教练态里 GROW 是唯一主线，朋友态的「话题拓宽/换话题」机制一律关闭，否则会和教练打架。

| 机制 | 朋友态 | 教练态 |
|---|---|---|
| `[CURIOSITY]` 好奇心底座（`buildCuriosityHint`） | ✅ 触发 | ❌ 关闭（把教练拽去闲聊） |
| nudge 好奇心找话题 | ✅ 触发 | ❌ 关闭 |
| `[TOPIC]` 换话题（追问太密/敷衍/低唤醒） | ✅ 触发 | ❌ 关闭（GROW 靠连续提问推进，追问太密是常态） |
| `[GOAL]` 课题档案 | 照常注入 | 照常注入 |
| `[FOLLOW_UP]`「后来呢」 | 新通话首轮触发（每通一次） | 教练自己问 |
| 静默主动发话（followup/nudge/farewell） | ✅ 按 5s/10s/多次触发 | ❌ 关闭（30s 轻轻 checkin → 再 30s 温柔留门收尾） |

### 6.5 主动追问（跨会话问责）

新通话首轮、对方仍在**朋友态**时，若存在「有下一步（`will`）未完成」的进行中课题 → 注入 `[FOLLOW_UP]` 块温柔追问「后来呢」（每通一次，`goalFollowUpDone` 锁）。解决后课题标记 done，下次不再追问，闭环收口。

### 6.6 静默主动发话（教练态更耐心）

> 教练态里用户沉默多半是在「想/消化」（尤其聊到原生家庭、配得感这类重话题），
> 朋友态那套静默主动发话会打断思考、变成唠叨——所以教练态单独走一条更耐心的策略（`armIdleCheck` 开头短路）。

- **教练态**：不 `followup`（自问自答「如果是我的话…」）、不 `nudge`（找话题）、不 `farewell`（失落收尾）。两阶段：
  ① 沉默超过 `COACH_SILENT_MS = 30000`（朋友态 nudge 的 3 倍）→ 轻轻 `checkin` 一次（「还在吗」）；
  ② 确认后仍无回应、再等 `COACH_CLOSE_MS = 30000` → `coachClose` 温柔留门收尾（「我在这儿，你想回来的时候我都在」）+ 挂断，不无限等。
  用户一旦开口（`markUserVoice`），`coachCheckinDone` 归零、重新计时。
- **朋友态**：维持原 5s 追问 / 10s 轻问 / 多次没答收尾的节奏。
