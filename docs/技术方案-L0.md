# 技术方案 · L0 通话前端（具体实现）

> 从 `技术方案.md` §三 L0 行拆出。浏览器端：麦克风采集、播放、前端 VAD 打断、极简通话 UI。已实现（`apps/client`）。

## 一、形态

- **栈**：Next.js 14（App Router）+ React 18 + TS，纯前端，无 UI 组件库（自绘）。
- **单页状态机**：`app/page.tsx` 一个组件承载四个视图 `contacts / add / detail / call`，用 `useState<'contacts'|'add'|'detail'|'call'>` 切换；`layout.tsx` 套一个手机壳（顶部 `StatusBar` 状态栏 + `home-indicator`）。
- **服务地址**：`process.env.NEXT_PUBLIC_SERVER_URL ?? 'http://localhost:3001'`。

## 二、四个视图

| 视图 | 干什么 | 关键接口 |
|---|---|---|
| `contacts` 通讯录 | 已添加伙伴列表 + 搜索 + 移除 | `GET /contacts`、`DELETE /contacts/:name` |
| `add` 添加伙伴 | 全量 16 位伙伴卡片，可看详情 / 添加（未上线者置灰） | `POST /contacts` |
| `detail` 详情 | 关于 TA / 说话风格 / TA 擅长帮你 | 纯本地数据 |
| `call` 通话 | 接通/挂断/静音/通话状态 | `POST /rtc/offer`、`GET /health` |

- **伙伴数据** `app/companions.ts`：16 位 `Companion`，字段 `name/gender/temperament/profession/intro/style/strength/color/available`。对外只展示「姓名 + 一句气质 + 职业」，**不展示 MBTI**；`available: true` 才可打电话（当前 4 位：程书衡 / 沈砚秋 / 沈知遥 / 苏明悦）。
- **通讯录持久化在后端**（Postgres `contacts` 表），前端启动时 `GET /contacts` 拉已添加名单，`added` 用 `Record<name, boolean>` 维护。服务端首次启动会**预置默认伙伴「苏明悦」**（`store/contacts.ts` 的 `seedDefaults`，仅通讯录为空时播种一次，不覆盖用户后续增删）。

## 三、接通流程（`start()`）

```
getUserMedia({audio:true})               // 麦克风
 → new RTCPeerConnection()               // 浏览器原生
 → addTrack(音轨)                        // 上行
 → createDataChannel('control')          // 打断信令通道
 → new AudioContext() + resume()
 → pc.ontrack → 动态 <audio> autoplay    // 下行播放
 → createOffer → setLocalDescription → waitForIceGathering(非trickle)
 → POST /rtc/offer { sdp, name }        // 信令（带 name 选人）
 → setRemoteDescription(answer)          // 接通
 → startVad() + startHealthPoll()
```

## 四、前端 VAD 打断（`startVad()`）

- **原理**：`AudioContext.createMediaStreamSource` → `AnalyserNode`（`fftSize=1024`）→ `getByteTimeDomainData` 拿时域样本，算 RMS；`rms > 0.15` 判「在说话」（阈值调高避免回声误判）。
- **上升沿触发**：`speaking && !wasSpeaking` 时才发一次打断，经 data channel 发 `{"type":"interrupt"}`；`wasSpeaking` 记录上一帧状态。
- **驱动**：`requestAnimationFrame` 循环，`vadRunningRef` 控制启停（挂断即停）。
- **打断语义**：你开口 → 服务端收到信令 → 清播放队列、abort 本轮 TTS，立刻转去听你。

## 五、下行播放

- `pc.ontrack` 拿远端音轨，`new MediaStream([track])` 挂到动态创建的 `<audio autoplay>` 上；每个 `<audio>` 记进 `audioElsRef`，挂断统一摘除。
- 浏览器原生 WebRTC 负责 Opus 解码，前端**不手动碰 PCM**（解码/编码都在服务端 werift + OpusScript）。

## 六、健康轮询（防静默黑屏）

- `startHealthPoll()` 每 3s `GET /health`；失败 → `stop()` 清理 + 顶部浮层提示「连接已断开」+ 弹回通讯录。后端进程一挂，前端立刻感知而不是黑屏等死。

## 七、挂断 / 静音 / 清理

- **静音**：`toggleMute()` 切 `track.enabled`（禁用麦克风音轨），静音后 VAD 拿不到能量，也不会误触发打断。
- **挂断清理**（`stop()`）：停 VAD、停健康轮询、摘掉所有 `<audio>`、关 `AudioContext`、`pc.close()`、`stream.getTracks().forEach(t => t.stop())` —— 每次通话不残留节点/上下文。

## 八、开发 / 运行

- `npm run dev`（`next dev -p 3000`），生产 `next build`。
- 前端只负责采集/播放/打断，**不承载任何大脑逻辑**；情绪打分、记忆、TTS 指令全在后端。
